# مشارکت در KeyFlip

ممنون که می‌خواهید در KeyFlip مشارکت کنید. این راهنما مسیر پیشنهادی را کوتاه توضیح می‌دهد.

## گزارش مشکل

قبل از باز کردن Issue جدید، Issueهای موجود را جست‌وجو کنید. در گزارش این موارد را بنویسید:

- نسخه ویندوز و نسخه KeyFlip.
- حالت انتخاب‌شده (خودکار، دستی و...) و برنامه‌ای که در آن تایپ می‌کردید.
- متنی که تایپ کردید، نتیجه‌ای که انتظار داشتید و نتیجه‌ای که گرفتید.
- برای خطاهای تشخیص: اگر برنامه را در حالت Debug اجرا کنید، فایل `%AppData%\KeyFlip\debug.log` کمک بزرگی است.

## پیشنهاد قابلیت

ابتدا یک Issue باز کنید و مشکل یا نیاز را توضیح دهید، نه فقط راه‌حل را. این کار از زحمت بی‌مورد جلوگیری می‌کند.

## راه‌اندازی محیط توسعه

پیش‌نیاز: ویندوز، .NET 10 SDK، Python 3 و یک IDE (Rider یا Visual Studio).

```
git clone <آدرس مخزن شما>
cd KeyFlip
python tools/prepare_data.py
dotnet build
```

فایل `Fonts/Vazirmatn-Regular.ttf` را در پوشه `Fonts` بگذارید. بدون آن برنامه با Segoe UI اجرا می‌شود.

## ساختار پروژه

```
Core/    منطق برنامه: hook کیبورد، تشخیص زبان، تبدیل متن، تنظیمات
UI/      پنجره‌ها و کنترل‌های سفارشی WinForms
Data/    لیست کلمات (با tools/prepare_data.py ساخته می‌شود)
Fonts/   فونت Vazirmatn
Assets/  آیکون برنامه
tools/   اسکریپت‌های کمکی
```

بخش‌های مهم:

- `Core/ConversionEngine.cs`: جریان اصلی تصمیم‌گیری.
- `Core/LanguageDetector.cs`: فهرست کلمات، ریخت‌شناسی و مدل n-gram.
- `Core/KeyMap.cs`: نگاشت کلیدهای انگلیسی به فارسی.
- `Core/ManualConverter.cs`: حالت دستی.
- `UI/`: ظاهر برنامه.

## قواعد کدنویسی

- کد باید شیءگرا و خوانا باشد؛ هر کلاس یک مسئولیت داشته باشد.
- برای متغیرهای محلی از `var` استفاده کنید.
- فقط جایی کامنت بنویسید که کد به‌تنهایی گویا نیست.
- به عملکرد توجه کنید: callback مربوط به hook کیبورد باید بسیار سریع برگردد. کار سنگین، دسترسی به فایل و `SendInput` را روی thread دیگر انجام دهید. دلیلش این است که ویندوز hookهای کند را بی‌صدا حذف می‌کند.
- رابط کاربری باید با DPIهای مختلف درست دیده شود (از مقیاس‌دهی `S(...)` در کلاس‌های UI استفاده کنید).
- ثابت‌های تجربی تشخیص (آستانه‌ها و اندازه فهرست‌ها) را بدون مثال یا اندازه‌گیری تغییر ندهید و در توضیح PR بنویسید چه چیزی را تست کرده‌اید.

## تست

فعلاً تست خودکار ندارد، پس تغییرات را دستی امتحان کنید. حداقل این سناریوها:

1. تایپ `ljk ` با کیبورد انگلیسی (باید «متن» شود) و `فاهس ` با کیبورد فارسی (باید `this` شود).
2. Undo با Backspace بلافاصله بعد از تبدیل.
3. حالت دستی با متن انتخاب‌شده و بدون انتخاب.
4. باز و بسته شدن پنجره تنظیمات و تغییر میانبر.

افزودن تست واحد برای `TextConverter`، `Morphology` و `NgramModel` مشارکتی بسیار ارزشمند است.

## ارسال Pull Request

1. مخزن را Fork کنید و یک شاخه جدید بسازید، مثلاً `feature/short-name` یا `fix/short-name`.
2. تغییرات کوچک و متمرکز بفرستید و برای هر تغییر منطقی یک commit با پیام واضح بنویسید.
3. اگر رفتار برنامه عوض می‌شود، `README.md` را هم به‌روز کنید.
4. در توضیح PR بنویسید چه چیزی را تغییر داده‌اید، چرا، و چگونه تست کرده‌اید.
5. اگر لیست کلمات یا داده جدید اضافه می‌کنید، مجوز منبع را ذکر کنید.

با ارسال مشارکت، موافقت می‌کنید که کد شما تحت مجوز MIT پروژه منتشر شود.

## ایده‌های مناسب برای شروع

- پشتیبانی از چیدمان‌های دیگر فارسی و نگاشت Shift.
- تست‌های واحد.
- بهبود ریخت‌شناسی فارسی (مثلاً اتصال به دیکشنری Hunspell).
- تشخیص فیلد رمز در مرورگرها و برنامه‌های مدرن (UI Automation).
- پشتیبانی از زبان‌های دیگر.

# Contributing to KeyFlip

Thanks for your interest in contributing. This guide describes the suggested workflow.

## Reporting bugs

Search existing issues before opening a new one. Please include:

- Your Windows version and KeyFlip version.
- The selected mode (Auto, Manual, ...) and the app you were typing in.
- The text you typed, what you expected, and what happened.
- For detection problems: if you run a Debug build, `%AppData%\KeyFlip\debug.log` helps a lot.

## Suggesting features

Open an issue first and describe the problem or need, not only the solution. This avoids wasted effort.

## Development setup

Requirements: Windows, .NET 10 SDK, Python 3, and an IDE (Rider or Visual Studio).

```
git clone <your fork url>
cd KeyFlip
python tools/prepare_data.py
dotnet build
```

Put `Fonts/Vazirmatn-Regular.ttf` in the `Fonts` folder. Without it the app falls back to Segoe UI.

## Project structure

```
Core/    app logic: keyboard hook, language detection, text conversion, settings
UI/      WinForms windows and custom controls
Data/    word lists (generated by tools/prepare_data.py)
Fonts/   Vazirmatn font
Assets/  app icon
tools/   helper scripts
```

Key files:

- `Core/ConversionEngine.cs`: the main decision flow.
- `Core/LanguageDetector.cs`: word lists, morphology and the n-gram model.
- `Core/KeyMap.cs`: English-to-Persian key mapping.
- `Core/ManualConverter.cs`: Manual mode.
- `UI/`: the look of the app.

## Coding guidelines

- Keep the code object-oriented and readable; one responsibility per class.
- Use `var` for local variables.
- Comment only where the code is not self-explanatory.
- Mind performance: the keyboard hook callback must return very fast. Do heavy work, file access and `SendInput` on another thread, because Windows silently removes slow hooks.
- The UI must look right at different DPI settings (use the `S(...)` scaling helper in UI classes).
- Do not change the empirical detection constants (thresholds, list sizes) without examples or measurements, and describe what you tested in the PR.

## Testing

There are no automated tests yet, so please verify changes by hand. At minimum:

1. Type `ljk ` on the English layout (should become "متن") and `فاهس ` on the Persian layout (should become `this`).
2. Undo with Backspace right after a conversion.
3. Manual mode with a selection and without one.
4. Open and close the settings popup and change the hotkey.

Unit tests for `TextConverter`, `Morphology` and `NgramModel` would be a very valuable contribution.

## Submitting a pull request

1. Fork the repository and create a branch, e.g. `feature/short-name` or `fix/short-name`.
2. Keep changes small and focused, with one clear commit message per logical change.
3. If behaviour changes, update `README.md` too.
4. In the PR description, say what changed, why, and how you tested it.
5. If you add word lists or other data, state the source's license.

By contributing, you agree that your code is released under the project's MIT License.

## Good first ideas

- Support for other Persian layouts and Shift mappings.
- Unit tests.
- Better Persian morphology (for example, plugging in a Hunspell dictionary).
- Password-field detection in browsers and modern apps (UI Automation).
- Support for other languages.
